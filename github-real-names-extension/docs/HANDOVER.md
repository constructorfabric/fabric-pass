# Передача: расширение GitHub Real Names

Для новой сессии. Здесь только то, чего **нет в коде** и что дорого добывалось заново.
Сам код читать всё равно придётся — он самодостаточен, с тестами и с комментариями,
объясняющими причины решений. Пересказ хода работы тут не нужен.

## Где что лежит

| | |
| --- | --- |
| `GHnameExt.md` | PRD, обновлённый под формат `contributors.yaml` |
| `PLAN.md` | план реализации; там же зафиксированы решения и их причины |
| `extension/` | код, 333 теста, git-репозиторий |
| `extension/README.md` | установка, сборка, откуда берутся данные |
| `extension/scripts/cdp/README.md` | как смотреть расширение на живых страницах GitHub |

Репозиторий: `https://github.com/lobster40/cf-user-extension-internal`, приватный, ветка `main`.
Лежит в личном аккаунте, потому что политика организации `constructorfabric` не даёт
участнику с ролью member создавать репозитории. Перенести в организацию потом можно без
потери истории через Settings → Transfer ownership, GitHub оставит редирект.

Проверка перед коммитом — `npm run check` (типы, линт, тесты).

## Правила, которые нельзя нарушать

**В репозитории не должно быть русского текста нигде** — ни в комментариях, ни в JSDoc,
ни в названиях тестов, ни в README. Единственное исключение — `public/_locales/ru/messages.json`,
где русский и есть содержимое. Проверять по всем файлам (`git ls-files`), а не по одному
каталогу: в прошлый раз проверка только по `src/` пропустила тесты и README.

**Не публиковать артефакты и отчёты без просьбы.** Файлы-результаты кладутся по обычному
пути внутри проекта, а не в session-scratchpad.

## Факты о разметке GitHub

Всё измерено на живых залогиненных страницах `constructorfabric/gears-rust`, а не выведено
из документации. GitHub отдаёт **разную разметку залогиненному и анонимному** пользователю,
поэтому фикстуры в `tests/fixtures/github/` (сняты curl-ом, то есть анонимно) не совпадают
с тем, что расширение видит в реальности. Это главная ловушка проекта.

* **Ссылки на людей появляются БЕЗ hovercard-атрибутов, атрибут дописывается позже.**
  На одной загрузке списка коммитов: 12 ссылок пришли сразу с `data-hovercard-url`,
  47 — без него, и **70** получили его отдельной мутацией (`oldValue: null`). Поэтому
  наблюдатель обязан следить и за атрибутами, а не только за добавлением узлов.
* **На момент запуска content script пользовательских ссылок на странице может быть ноль**
  (`readyState === "interactive"`). Первый синхронный проход на таких страницах не находит
  ничего, и весь результат даёт наблюдатель.
* **`href` пользовательской ссылки — не логин.** На списках issue и PR он ведёт в поисковый
  запрос вида `/OWNER/REPO/issues?q=…author%3Ajohnpapa`. Наивный разбор первого сегмента
  пути даёт имя организации.
* **На списке PR hovercard-атрибутов нет вообще.** Логин лежит в `href` как `author:<login>`
  и дублируется текстом ссылки; есть `data-testid="author-filter-link"`.
* **Классы Primer содержат хеш сборки** (`PullsListItem-module__filterLink__a5ZnW`,
  `prc-ActionList-ItemLabel-81ohH`) — меняются при каждом деплое, опираться нельзя.
* **`aria-label` локализуется** (`Filter by author …`) — опираться нельзя.
* **В выпадающих фильтрах `data-id` в двух несовместимых форматах**: у части строк старый
  base64 (`MDQ6VXNlcjg2MjYxOTU4` → `04:User86261958`, число совпадает с `github_id` в реестре),
  у части новый упакованный (`U_kgDOEfxP3g`), недокументированный. Сопоставлять по нему нельзя —
  половина строк не разберётся. Если однажды понадобится сопоставление по идентификатору,
  брать его из адреса аватара: `avatars.githubusercontent.com/u/20254119`.
* **У строк-людей в выпадашках есть аватар GitHub**, у ярлыков и майлстоунов — нет. Компонент
  ActionList общий, так что без проверки аватара логин вида `docs` разметил бы строку ярлыка.
* **Один человек на странице PR встречается несколькими ссылками** с одинаковыми атрибутами
  (аватар, имя текстом, аватар в стеке коммитов). Декорировать надо только те, у которых есть
  собственный видимый текст.
* **App-аккаунты выводятся как `github-actions[bot]`**, а в `href` лежит `github-actions`.
  Сверка текста с логином их отсекает, и это осознанно: показывать боту имя нечего.

## Проверенные тупики — не тратить время заново

* **`--load-extension` в Chrome 153 не работает.** Расширение молча не загружается.
  Грузить через протокол: `node scripts/cdp/load-extension.mjs`.
* **`--disable-extensions-except` отключает всё**, включая загруженное руками. Не передавать.
  Однажды это выглядело как полный регресс расширения.
* **`requestAnimationFrame` не вызывается в скрытой вкладке**, а вкладка считается скрытой,
  когда окно не в фокусе на уровне системы. `Page.bringToFront` и `Emulation.setFocusEmulationEnabled`
  этого не меняют: фокус появляется, видимость нет. Сейчас разметка от кадра не зависит,
  но любой замер, ожидающий кадра, в скрытой вкладке повиснет.
* **Навигация на `chrome-extension://…/options.html` через протокол блокируется** — отдаётся
  страница-заглушка. К API расширения ходить через его service worker.
* **Service worker не виден в списке целей, пока спит.** Будится перезагрузкой расширения.
* **React ничего не стирает.** Гипотеза, что он выбрасывает наши вставки, проверена и неверна:
  флаг `data-ghname-done` остался бы на элементах, а он нулевой.

## Открытые вопросы

**Релиз не выпущен.** Версия в `package.json` — `0.1.0`. Выпуск: поднять версию, поставить
тег `vX.Y.Z`, запушить тег — CI соберёт оба архива и опубликует. Workflow проверяет, что тег
совпадает с версией.

**Расширение ни разу не ставилось в основной браузер Anatoly.** Всё проверялось в отладочном
профиле. Встроенный источник там работает: статус `ok`, 64 записи из приватного `cf-internal`
сессией браузера.

**Firefox: постоянная установка требует подписи в AMO.** `Load Temporary Add-on` живёт до
перезапуска браузера. Подпись бесплатна, но это отдельный шаг, он не сделан.

**Safari не поддержан.** Сборка `wxt build -b safari` проходит, но Safari требует обёртку в
нативное приложение через `xcrun safari-web-extension-converter`, а для этого нужен полный
Xcode (на машине только Command Line Tools). Плюс `permissions.request` в Safari работает
иначе — источник по URL там, скорее всего, придётся переделывать.

**Название репозитория.** Anatoly просил `cf-userExtention-internal`; я взял
`cf-user-extension-internal` — без опечатки в слове Extension и в стиле `cf-internal`.

## Принятые продуктовые решения

**Приоритет у реестра над профильным именем GitHub.** В выпадающих фильтрах GitHub местами
уже показывает своё имя. Если запись есть в реестре — показывается имя из реестра, а
профильное скрывается; записи нет — строка не трогается. Плата за правило видна на
`AndrejK666`: в реестре у него `Andrej`, а GitHub показывает `ANDREI KUCHMA`, то есть
информативнее. Лечится записью в реестре, не кодом.

**Скрытие профильного имени обязано быть обратимым.** Та же функция снятия разметки работает
при смене формата отображения и при выключении расширения. Тест сравнивает разметку строки
побайтово до и после.

**Все форматы отображения — «логин, разделитель, имя»**, различаются только разделителем
(`·`, `( )`, `[ ]`). Изначально в PRD был формат `Имя [логин]`, но он недостижим: логин лежит
внутри чужой ссылки GitHub, а вставка возможна только после элемента. Превью в настройках
теперь строится вызовом той же функции, что формирует текст на странице, — разойтись они
не могут.

**Неудачная загрузка встроенного источника никогда не затирает записи.** 404, обрыв сети,
битые данные, пустой ответ — обновляется только статус. Пустой результат считается неудачей
намеренно: корпоративный реестр пустым не бывает, а отдать пустоту при сбое GitHub может, и
это стёрло бы имена всем.

**Дублем считается только логин, реально попавший в индекс.** Запись, пропущенная по другой
причине, не блокирует следующую валидную с тем же логином: иначе пара
`{alice, name: null}` перед `{alice, name: "Alice Smith"}` молча съедала бы имя.

## Как устроена работа с агентами

Реализация шла через субагентов по волнам, спецификации в `PLAN.md`. Что стоит повторить:

* **сначала контракты.** Типы и фикстуры пишутся до того, как параллельные агенты начнут
  работу, иначе они придумают несовместимые интерфейсы;
* **делить задачи по файлам, а не по темам.** Два агента в одном файле дают коллизию —
  это случилось один раз на `src/core/messages.ts`;
* **запрещать опору на ненадёжные признаки прямо в спецификации.** Хешированные классы и
  локализуемые подписи агент возьмёт, если не запретить: они выглядят удобно;
* **требовать проверки, а не рассуждений.** Формулировка «проверь по факту и покажи вывод»
  ловила реальные расхождения; несколько агентов честно сообщали, что спецификация
  расходится с действительностью, и были правы.
